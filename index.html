    方法與來源 · 示範資料授權（Apache-2.0、MIT）

    貼上 MCP 伺服器的 tools/list 結果、SKILL.md，或把整個 skills 資料夾拖進來。這個工具找出名字和描述太像、模型可能選錯的「雙胞胎」，並估算每個項目佔多少 token。全部在瀏覽器內計算，不會上傳。

    檢查工具只看單一 skill；工具雙胞胎看它們彼此之間。

    相似度用 TF-IDF 加餘弦距離，比較名稱、描述與參數名稱；英文會合併詞形（file／files）與常見同義動詞（get／fetch、delete／remove），中文用兩字詞片段。名稱開頭是已知動詞時，動作不同、或動作相同但物件互不相干的兩個工具，分數減半。skill 只比較描述：相似度 ≥ 0.50，或共用觸發詞（兩個詞，或一個引號短語）且相似度 ≥ 0.30，而且兩邊都沒有指向對方的排除說明或轉交句（例如「For …, use 另一個 skill」）時，列為需要先處理；只共用觸發詞、相似度低於 0.30 的組合放在摺疊的弱訊號區塊。這是啟發式檢查，可能誤報，也可能漏報；分數和標籤只是提示，不是定論，也不是模型實際的選擇機率。token 數是以字元數換算的估計值。

    token 是估算值：英文約 4 個字元算 1 個，中日韓文約 1.25 個字元算 1 個。各模型的 tokenizer 不同，實際數字會有出入。MCP 工具計算名稱、描述與 inputSchema；skill 只計算啟動時載入的名稱與描述。

    skills 放在哪：Claude Code 的個人 skills 在 ~/.claude/skills，專案層級的在 .claude/skills。其他工具據說使用 .agents/skills/ 與 .github/skills/（未經驗證）。選資料夾時只讀取裡面的 SKILL.md。

    示範資料逐字取自公開 repo：skill-creator、webapp-testing 來自 github.com/anthropics/skills（Apache-2.0）；writing-skills、executing-plans、subagent-driven-development、requesting-code-review、receiving-code-review 來自 github.com/obra/superpowers（MIT，© 2025 Jesse Vincent）；browser_* 工具來自 @playwright/mcp 0.0.83（Apache-2.0，© Microsoft）；read_* 工具來自 @modelcontextprotocol/server-filesystem 2026.8.31（Apache-2.0／MIT）。
